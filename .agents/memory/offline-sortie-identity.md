---
name: Offline sortie identity
description: Why sortie IDs are generated before dispatch reaches the server.
---

Field sortie IDs must be generated by the client and included in the queued dispatch command. Later beacon, return, and close commands can be queued before the server receives the dispatch, so each needs the final sortie ID from the start.

**Why:** A server-generated ID would leave dependent offline commands pointing at a temporary identifier that changes during replay.

**How to apply:** Preserve the client UUID through dispatch, idempotent replay, and snapshot refresh. Keep each command's idempotency key separate from the sortie's domain ID.
